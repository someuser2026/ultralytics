WINDOWS SELECTIVE-SCAN INSTALLATION AND TEST HANDOFF
Updated: 6 November 2026
Package: selective-scan-windows 0.1.0

PURPOSE
Install the new independent Windows CUDA package, test it, and send the logs
back. The original selective_scan and ultralytics source files are unchanged.
Windows compilation and GPU tests have NOT yet been verified on this PC.

READ THIS FIRST
- Open a fresh Command Prompt (cmd.exe) from Start; section 2 initializes the
  VS 2022 x64 compiler. Do not launch it from an existing developer shell.
  These are Command Prompt commands, NOT commands to paste into PowerShell.
  Commands beginning with "powershell -NoProfile" launch PowerShell themselves;
  paste those commands into the same Command Prompt too.
- Run one numbered section at a time. Paste each command on its own line.
- Do not continue after an unexpected failure. Go to section 10 and send the
  logs already produced. Failed builds are useful diagnostic results.
- Keep the same Command Prompt open: its variables and compiler environment
  are used by later sections. Logs are redirected to files, so some commands
  show no progress on screen while they run. Wait until the prompt returns.
- Closing the window loses variables set with "set". In a new window, rerun
  all of section 2. "cls" only clears the screen and preserves the variables.
- Do not run "pip install" from the original selective_scan directory.
- Do not remove the original package from an existing environment. If that
  package is installed, use a separate Windows environment instead.

REQUIRED SOFTWARE
The PC setup guide should already have installed:
  * NVIDIA driver, with nvidia-smi working.
  * micromamba, available on PATH.
  * Visual Studio 2022 Build Tools, Desktop development with C++, a Windows
    SDK, and MSVC v143 toolset v14.38 (compiler 19.38).
  * CUDA Toolkit 12.6 Update 3, including nvcc.exe.
  * A local copy of the custom ultralytics repository.

If these are not installed, complete that setup first. Installer locations:
  VS 2022 Build Tools: https://aka.ms/vs/17/release/vs_BuildTools.exe
  CUDA 12.6 Update 3: https://developer.nvidia.com/cuda-12-6-3-download-archive
  micromamba: https://mamba.readthedocs.io/en/latest/installation/micromamba-installation.html

The Python environment and Python dependencies can be installed below.
No WSL or Ubuntu is involved. R2/rclone credentials are not needed for testing.

RETURNING AFTER THE STEP 5 BUILD FAILURE
Your existing CUDA 12.6 (V12.6.85), PyTorch 2.8.0+cu126, and environment can
be reused. Adding MSVC 14.38 does not require reinstalling CUDA or PyTorch.
After the updated source has been committed AND pushed from the development
machine, run section 1 on the Windows PC, then all of section 2 in a fresh
Command Prompt. If sections 3 and 4 previously passed and the environment
has not changed, skip their installation commands and go to section 5R.
Section 5R checks the environment before rebuilding. If you removed/recreated
the environment, complete sections 3 and 4 first.

1. PUT THE NEW CODE ON THE PC
======================================================================

The package and this guide are on the rip-detectionv2 branch of the custom
ultralytics repository. In Command Prompt, update an existing Git checkout:

cd /d "%USERPROFILE%\rip-work\repos\ultralytics"
git status --short

If git status shows local edits, stop and retain those files before updating.
Do not reset or delete them. With a clean checkout, run one line at a time:

git fetch origin
git switch rip-detectionv2
git pull --ff-only origin rip-detectionv2
git log -1 --oneline

Stop if any Git command fails. A local commit on the development machine is
not available to this PC until it has been pushed to origin. Source updates
use Git; no source ZIP transfer is needed. Confirm the dispatch fix is present:

git merge-base --is-ancestor 7304d1a2 HEAD
echo dispatch_fix_present_exit=%ERRORLEVEL%

Expected: exit 0. If it is nonzero, do not retry the build with this checkout.

Expected layout:
  C:\Users\YOUR_USER\rip-work\repos\ultralytics\pyproject.toml
  C:\Users\YOUR_USER\rip-work\repos\ultralytics\ultralytics\
  C:\Users\YOUR_USER\rip-work\repos\ultralytics\selective_scan\

After updating with Git, confirm the same files exist.

2. OPEN THE DEVELOPER COMMAND PROMPT AND START A LOG FOLDER
======================================================================

Open Start -> Command Prompt (cmd.exe).
Run the following. Change ONLY the SSW_REPO path if the repo is elsewhere:

set "SSW_REPO=%USERPROFILE%\rip-work\repos\ultralytics"
set "SSW_ENV=ultralytics_contrib"
set "SSW_RUN=%SSW_REPO%\selective_scan_windows\logs\run-%RANDOM%-%RANDOM%"
mkdir "%SSW_RUN%"
echo Windows selective scan test > "%SSW_RUN%\status.txt"
echo Started=%DATE% %TIME% >> "%SSW_RUN%\status.txt"
echo Repository=%SSW_REPO% >> "%SSW_RUN%\status.txt"
echo Environment=%SSW_ENV% >> "%SSW_RUN%\status.txt"
git -C "%SSW_REPO%" rev-parse HEAD > "%SSW_RUN%\00_revision.txt" 2>&1
echo Logs=%SSW_RUN%
dir "%SSW_REPO%\selective_scan_windows\setup.py"
dir "%SSW_REPO%\pyproject.toml"

Both dir commands must find their files. If they do not, fix the folder layout
or SSW_REPO before continuing. Note the Logs path printed above.
This logs folder is ignored by Git; it is not transferred by git pull/push.
status.txt is inside this attempt's folder. To find or read it later in this
same window, run "echo %SSW_RUN%\status.txt" or "type %SSW_RUN%\status.txt".

Choose the intended compiler (default VS Build Tools installation path):

call "%ProgramFiles(x86)%\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvarsall.bat" x64 -vcvars_ver=14.38 > "%SSW_RUN%\01_compiler_setup.txt" 2>&1
echo compiler_setup_exit=%ERRORLEVEL% >> "%SSW_RUN%\status.txt"
type "%SSW_RUN%\01_compiler_setup.txt"
set "DISTUTILS_USE_SDK=1"
where cl > "%SSW_RUN%\02_compiler_environment.txt" 2>&1
echo VCToolsVersion=%VCToolsVersion% >> "%SSW_RUN%\02_compiler_environment.txt"
echo INCLUDE=%INCLUDE% >> "%SSW_RUN%\02_compiler_environment.txt"
type "%SSW_RUN%\02_compiler_environment.txt"
cl > "%SSW_RUN%\02_compiler_version.txt" 2>&1
type "%SSW_RUN%\02_compiler_version.txt"

Expected: compiler_setup_exit=0; compiler version 19.38... for x64;
VCToolsVersion=14.38...; first cl path and MSVC include paths use 14.38.
If 14.44 include paths appear, restart from a fresh ordinary Command Prompt
opened from Start and rerun section 2. Call vcvarsall only once per fresh window.
The "missing source filename" error from cl alone is EXPECTED: this command
only asks it to print its version. If VS is installed elsewhere, adjust the
vcvarsall.bat path. Do not substitute a newer compiler silently.
DISTUTILS_USE_SDK=1 tells PyTorch/setuptools to reuse this compiler environment.
Set it again after compiler activation if you open another Command Prompt.

Select the default CUDA 12.6 toolkit location:

set "CUDA_PATH=C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.6"
set "CUDA_HOME=%CUDA_PATH%"
set "PATH=%CUDA_PATH%\bin;%PATH%"
set "MAX_JOBS=2"
set "TORCH_CUDA_ARCH_LIST="
nvcc --version > "%SSW_RUN%\03_nvcc.txt" 2>&1
echo nvcc_exit=%ERRORLEVEL% >> "%SSW_RUN%\status.txt"
type "%SSW_RUN%\03_nvcc.txt"
nvidia-smi > "%SSW_RUN%\04_nvidia_smi.txt" 2>&1
echo nvidia_smi_exit=%ERRORLEVEL% >> "%SSW_RUN%\status.txt"
type "%SSW_RUN%\04_nvidia_smi.txt"
micromamba --version > "%SSW_RUN%\05_micromamba.txt" 2>&1
echo micromamba_exit=%ERRORLEVEL% >> "%SSW_RUN%\status.txt"
type "%SSW_RUN%\05_micromamba.txt"

Expected: each exit code 0; nvcc release 12.6; NVIDIA A1000 visible.
The CUDA Version displayed by nvidia-smi is the driver's supported version,
which can be newer than 12.6. That is different from the toolkit version.
If CUDA was installed elsewhere, adjust CUDA_PATH to that v12.6 installation.
The architecture variable is cleared so the build detects the actual GPU.

7. VERIFY A REAL CHECKPOINT (IF WEIGHTS AND TILES ARE AVAILABLE)
======================================================================

This step is additional to kernel tests. If the owner has not supplied the
research checkpoint and sample tiles, skip it and say "checkpoint not supplied"
in the message sent back. Do not download a different public model as a substitute.

Transfer an existing research .pt checkpoint and two representative PNG tiles,
each exactly 448 x 448. EDIT these three paths to the actual files:

set "SSW_CHECKPOINT=%USERPROFILE%\rip-work\models\best.pt"
set "SSW_TILE1=%USERPROFILE%\rip-work\data\tile1.png"
set "SSW_TILE2=%USERPROFILE%\rip-work\data\tile2.png"
dir "%SSW_CHECKPOINT%"
dir "%SSW_TILE1%"
dir "%SSW_TILE2%"

All three files must exist. Then run:

micromamba run -n "%SSW_ENV%" python tools\validate_checkpoint.py --checkpoint "%SSW_CHECKPOINT%" --images "%SSW_TILE1%" "%SSW_TILE2%" --output "%SSW_RUN%\checkpoint" > "%SSW_RUN%\17_checkpoint.txt" 2>&1
echo checkpoint_exit=%ERRORLEVEL% >> "%SSW_RUN%\status.txt"
type "%SSW_RUN%\17_checkpoint.txt"

Expected: exit 0 and "inference_status": "passed" in checkpoint\report.json.
"baseline_status": "not_provided" is expected unless a comparison baseline
was explicitly supplied. It does NOT establish equality with HPC predictions.

The report records latency and peak/live GPU memory. Defaults: one tile at a
time, imgsz 448, full precision, confidence 0.25, IoU 0.7, max detections 300,
retina masks disabled, two warm-up passes and five measured passes. If the
owner supplied different prediction thresholds, append the corresponding
--conf, --iou, --max-det or --retina-masks arguments before running.

Outputs are checkpoint\report.json and checkpoint\predictions.npz. Send both.
This does not upload anything to R2, save annotated images, or delete input data.
The output directory must be new. To repeat, use a fresh output subfolder such
as "%SSW_RUN%\checkpoint-repeat" and a different log filename.
